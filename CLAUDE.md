# CLAUDE.md — правила проекта VarKa

## Источник истины и деплой
- **Рабочая копия и источник истины — ЭТОТ репозиторий:** `Desktop/CRM/проект VarKa`
  (remote `origin` = `github.com/cardexpress1-pixel/Varka-crm`, ветка `main`, хостинг GitHub Pages → `cardexpress1-pixel.github.io/Varka-crm/`).
- **НЕ работать в `Desktop/VarKa`** — это устаревшая копия, не подключённая к git. Все правки — только здесь.
- **Деплой:** правка `index.html` → `git commit` → `git push origin main` → GitHub Pages пересобирает сайт. Боевой сайт = `origin/main`.
- **`git push` / публикация — ТОЛЬКО с явным подтверждением пользователя («go»).** Перед пушем показать: репозиторий, remote, ветку, `git status`, изменённые файлы, краткий diff.

## Работа с данными (Firestore) — критично
- **Firebase Project ID — `varka-test` — это БОЕВОЙ проект, несмотря на имя.** Не создавать тестовые данные здесь.
- Приложение подключено к **ЖИВОМУ** Firebase/Firestore: всё состояние в одном документе `varka/state` (поле `_rev`). **В приложении нет резервного копирования.**
- **НИКОГДА не запускать/проверять приложение способом, который может вызвать запись в боевую БД.** Записью считать не только явный save, но и любые обработчики, дергающие `saveState()` внутри: смена темы (`toggleTheme`), навигация, клики.
- Проверять только на **изолированной копии**: обнулить Firebase-конфиг, или запускать офлайн, или подставить мок-стейт. Никогда — поверх живого документа.
- **Любая запись в общий/внешний ресурс (Firestore, git push) — только с явного согласия пользователя.**
- Инцидент 2026-07-04: проверка редизайна поверх живой БД затёрла реальные варки демо-данными; восстановлено реконструкцией из `journalEntries` + `wpGenerated`. Локальная страховка данных — `Desktop/VarKa/recovery/`. Подробности — `tasks/lessons.md`.

## Непрерывность сессий (команды «стоп сессия» / «новая сессия»)
- Пользователь пишет **«стоп сессия»** → обновить `SESSION_STATE.md` в репозитории: дата; что сделано за сессию; текущее состояние (что на боевом / что в работе, актуальный HEAD); **точные следующие шаги**; открытые вопросы; ссылки на детали (`DASHBOARD_PROGRESS.md`, `tasks/todo.md`, `tasks/lessons.md`). Затем `commit` + `push` **только `SESSION_STATE.md` и другие .md-доки** (чтобы состояние было доступно в новой сессии на любом устройстве). Код приложения этой командой НЕ пушить — для него по-прежнему нужен отдельный «go».
- Пользователь пишет **«новая сессия»** → ПЕРВЫМ делом прочитать `SESSION_STATE.md`, кратко пересказать «где остановились» и продолжить с раздела «Следующие шаги», не выпадая из контекста.
- `SESSION_STATE.md` — единый документ «где мы остановились». Держать коротким и актуальным.

## Хранение бэкапов index.html
- Хранить в корне не более 5 последних index.html.bak_*.
- Перед созданием нового backup: если бэкапов уже 5 — самый старый
  (по дате в имени файла) переносить (не удалять) в
  _archive/index_backups/.

## Изоляция от соседних проектов platform varka.kz
Чтение и запись за пределами этого репозитория **запрещены явным
deny-правилом** в `.claude/settings.local.json` (permissions.deny,
Read-паттерны на соседние папки: Tracker, varka-kanban, Project_Kanban,
00Project_portal_varka_kz) — это машинно-специфичный конфиг, НЕ
отслеживается git (см. `.gitignore`), а не просто соглашение/договорённость
в документации. Действует только для сессий Claude Code, открытых из
`Desktop/CRM/проект VarKa` (рабочая директория для этого проекта — именно
эта папка, не `Desktop/CRM`). Если открываешь новую сессию на другой
машине/копии этой папки, правило нужно настроить заново.
