## №1 — главная брешь (доказана инцидентом 2026-07-04)

Приложение входит в Firebase **анонимно**, весь стейт лежит в одном документе `varka/state`,
который читается **до логина** и пишется любым клиентом. Сайт на GitHub Pages публичный ⇒
любой человек, знающий URL, может открыть консоль браузера и прочитать/переписать/стереть все данные
(включая пароли ролей — п.2). Экранный логин его не остановит (п.3).

### Что сделать сейчас (Firebase Console → Firestore → Rules), 5 минут:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /varka/state {
      allow read: if request.auth != null;
      // запись только со строгим приращением версии и без удаления документа
      allow update: if request.auth != null
        && request.resource.data._rev == resource.data._rev + 1;
      allow create: if request.auth != null;
      allow delete: if false;
    }
    match /users/{uid} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == uid;
    }
    match /activityLog/{doc} {
      allow create: if request.auth != null;
      allow read: if request.auth != null;
      allow update, delete: if false; // журнал действий неизменяем
    }
    match /{document=**} { allow read, write: if false; }
  }
}
```

Это блокирует: удаление документа, перезапись журнала действий, запись без приращения `_rev`
(защита от отката «уснувшей» вкладкой и от сегодняшнего сценария затирания).

**Честно:** пока вход анонимный, полноценной защиты правила не дают — злоумышленник тоже может
войти анонимно и сделать «правильную» запись. Правила выше — обязательный минимум, а не финал.

### Этап 2 — настоящее решение (требует решения владельца):
перевод входа на именные аккаунты Firebase Authentication (email/password для admin/operator/
warshchik/intake) + правила по `request.auth.uid`. Тогда писать сможет только реально
вошедший сотрудник, а пароли уйдут из документа данных. Оценка: ~1 час работы в коде
+ создание 4 аккаунтов в консоли. Реализуется по команде «go».

## Что уже закрыто в коде (этот коммит)

1. **Анти-XSS**: `sanitizeStateUserText()` в `saveState()` — во всех полях, куда пользователи вводят
   текст (партии, заявки, клиенты, рецепты, роли, реакторы, линии, брендинг), угловые скобки
   заменяются на безопасные ‹ › до записи. Введённый скрипт не исполнится ни у кого.
2. **Резервные копии**: кольцо последних 5 версий стейта в localStorage (`backupRingPush()` при каждом
   сохранении и ПЕРЕД приёмом данных из облака). Восстановление: в консоли `varkaBackups()` (список)
   и `varkaRestoreBackup(N)` (откат с подтверждением). Плюс кнопка «Резервная копия» в админ-панели —
   скачивает весь стейт JSON-файлом.
3. **SRI** для `xlsx.full.min.js` (cdnjs): подменённый на CDN файл браузер не исполнит.
4. **Маскировка пароля** в редакторе ролей.
