# Уроки проекта VarKa

## 2026-07-29 — Убирая точку входа, проверь ВСЕХ, кто ей пользовался

**Что случилось.** Коммит `43449fd` (2026-07-22) убрал собственную форму входа
Manufacture в пользу единого входа через портал. В расчёт взяли офисных сотрудников,
у которых есть аккаунты на varka.kz. Про цех забыли: `warshchik` и `intake` — это
локальные роли Производства с логином/паролем на общем планшете, аккаунтов на
портале у операторов нет. Для них редирект на портал — тупик. Простой цеха.

**Правило.** Перед удалением/заменой любого способа аутентификации перечислить
поимённо все категории пользователей, которые им пользуются, и для каждой назвать
её новый путь входа. Если хоть для одной ответа нет — правку не выкатывать.
Отдельно проверять «безаккаунтных» пользователей: общие терминалы, киоски,
цеховые планшеты. Они не пишут в чат и обнаруживаются последними.

**Признак того же класса ошибок.** «Мёртвый код оставлен в DOM, показать его больше
некому» — формулировка из того коммита. Если код оставляют «на всякий случай»,
значит уверенности в полноте охвата не было. Это повод перепроверить, а не
успокоиться.

## 2026-07-29 — Не считать адрес рабочим только потому, что он в документации

Цех всё это время открывал старую ссылку GitHub Pages (`main` + Firebase
`varka-test`), а не боевой `varka.kz/manufacture`. Старый адрес после переезда
11.07 никто не погасил: он отдавал HTTP 200 и выглядел живым, хотя хранилище за ним
уже холодное. Проверять надо не «отвечает ли адрес», а «в ту ли базу он пишет».
После любого переезда старый адрес гасить (редирект), а не оставлять «пусть
полежит» — иначе часть людей продолжит работать в копии, и данные разъедутся.
